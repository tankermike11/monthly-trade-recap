Monthly trade recap · concept

Each customer's month, written from their own trades

Once a month, every customer gets a short recap of how they traded: how far out they went, how they managed and rolled positions, how they exited. Code writes the facts; Claude reads every trade and describes the patterns, like a note from someone who watched the account. Every number comes from code, and every sentence Claude writes is checked twice before it goes out: once by code for the rules, once by a second Claude call against the trades.

Facts

30 to 60 month facts (how far out trades expired, how often they were rolled), per-trade facts (dates, rolls, results) and counts ("3 of 5 losing trades"). Each keeps the trades it came from. Code also writes every single-fact line.

Words

Claude describes the month

Claude reads every trade and writes what code can't: the overall picture and what stood out, naming patterns and specific trades. Numbers go in as placeholders; it never types one.

Rules

Code checks the wording

Lengths, no typed numbers, only real facts, trader terms without shorthand, no advice, no praise, no repeated units, the month's result left to code. A draft that breaks a rule is sent back once with the reason.

Claim check

A second Claude call checks the claims

A separate call reads every sentence, with the numbers filled in, beside the full list of trades, and flags anything false, overstated ("all", "every", "usually") or not in the data. One rewrite with the reason; if it still fails, the recap is held for a person.

The rules it works under

  • Claude never does math. Counts, profit and loss, ratios and dates come from tested code.
  • Every number traces back to the fills it came from, so any line can be audited.
  • It describes habits, never activity or wins: no "great month", no trade counts as achievements.
  • No advice and no predictions: never "you should" or "next month".
  • A losing month is named once, plainly, next to how the market moved.
  • Trader terms, spelled out: expiration, strike, premium, rolled out. No DTE, IVR or delta.

Every month, for every customer

The real run is built for 5,000 to 10,000 customers, too many to read one by one, so the checks decide what a person sees:

  • All recaps go out together through the Batch API, which costs half as much and takes up to a day. Writing and checking come to about six and a half cents a customer, or roughly $640 per 10,000.
  • A recap that fails a check gets one rewrite. If it fails again, or the customer's data has problems, it is held for review instead of sent.
  • A person reads every held recap and a random 5% sample of the ones that passed, in the review gallery.
  • Every run is archived and never overwritten: the facts, the request, each draft, the checks and the final recap for each customer, with a fingerprint of every file, so any line can be traced later.
